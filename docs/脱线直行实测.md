
产物位于 `.build/ground_test/`，正常固件产物不被覆盖。下载前停止PWM并备份原Flash，禁用自动解锁，按页写入并逐字节回读。下载只检查上电READY和显示，不触发运动。Keil普通工程仍生成原正常固件；脱线固件需用上述构建参数生成。

## 单轮操作

1. 启动时放稳小车，保持静止完成约1秒零偏校准；确认屏幕为 `GROUND READY`、`HEAD READY X+`，先松开两个按键。航向纠偏版已完成架空方向检查，当前130 RPM档建议在6米以上直线空地落地测试，人可随时按ModeChange/PB15停车或断电。
2. 拔掉USB串口和ST-Link，小车主控、电机保持正常电池供电。ST-Link电源输出不与电池供电并联。
3. 长按Start/PB14至少1秒，再松开。短按不会启动；上电一直按住Start也不会自动开始。
4. 屏幕 `WAIT 3 SEC` 倒计时3秒，然后 `RUN STRAIGHT` 运行10秒，前2秒目标由20升到130 RPM，之后保持8秒；第二行显示当前目标RPM。观察方向、跑偏、起转、卡顿与停车。按ModeChange可取消/停车；倒计时或运行时再按Start也取消/停车。
5. 输出取消后进入 `STOPPING`，至少等待1秒且编码器连续300ms静止后显示 `DONE STOP`；超过2秒仍不能确认静止则显示 `FAULT STOP`。静止判定依赖编码器，不等同于物理制动距离保证。
   直行版本停车后若有稳态数据，首行DONE H为相对起始航向的误差（度），第二行L/R为左右平均RPM，第三行PWM为左右平均输出，第四行C为左右触顶百分比、F为原因码。摘要累计每个10ms周期，排除前2秒升速及其后1秒。先拍下停车屏幕，再接回调试器，避免重新启动后RAM结果丢失而无法判断跑偏原因。
6. 每次上电只允许一轮，完成、取消或故障后不因按键再次起动。不要立即复位，以免清空记录。

## 读回数据

保持主控供电，停止后仅重新接入ST-Link信号线及GND，电源输出仍断开；不需要串口，不打开会自动下载或复位的IDE调试会话。

```powershell
python tools/ground_board.py
```

读取脚本先比对实时Flash与ELF，再直接读取RAM，不执行复位或运动指令。数据保存在 `.build/hardware_checks/ground_时间戳/`，包含构建身份、终态、错误码、100ms编码器/RPM/PWM轨迹、控制周期、故障与停止静止计数。RAM记录会在断电或复位后丢失；若必须断电停车，以人和设备为先，接受本轮记录丢失。

错误码1～7沿用control.h；100为前台超过100ms未响应，101为倒计时末未静止/采样过期，102为停止后2秒未确认静止，103为记录溢出。故障后先查原因，不自动重试或提高PWM。

## 验证边界

主机模拟覆盖完整限时运行、单次限制、计时回绕、上电按住/短按不触发、倒计时取消、两键停车、前台卡住、堵转、反向、控制周期异常与停车后持续运动。实际地面方向、负载、跑偏及机械平稳性由现场观察和读回数据共同确认。此模式不依赖红外，也不等于完整循迹验证。
