## 已落实的行为

1. 路口统一在完整穿过峰区后确认一次。宽度使用原始编码器位置差累计，按左右计数和保存，保留半计数；保留 20 计数宽度、500 ms 冷却的初始门限。启动时已经位于标记上，则忽略该初始标记，避免把 A 点重复作为下一个点。
2. 每 4 个已确认路口完成一个圈序列，圈距离按圈起点计算。默认至少 3000 计数；不足时进入圈序列故障，避免错误地继续补跑。多圈任务在完成一圈时更新圈起点。
3. ACBD 的 `LINE_TO_B`、`LINE_TO_A` 改为灰度控制，`TO_C`、`TO_D` 使用航向控制。两个 PD 的参数和历史误差相互独立，航向误差归一化到 ±180°；转向请求同时受基速的 80% 限制，路线请求不会使单轮目标反转。
4. IMU 初始化和校准必须成功才能出发；校准要求至少 90% 读成功，检查重力幅值、角速度范围和样本波动，失败不覆盖旧零偏。运行中 IMU 读失败或采样间隔超过 50 ms 立即取消输出。
5. ADC 只发布完整成功帧；任意通道采样失败立即停车。循线阶段连续 400 ms 丢线进入故障；各行驶阶段 10 秒未产生预期标记则停止。`route_config.h` 集中维护初始阈值及路线参数。
6. 普通 FSM 显示并保留故障原因。按键不会自动续跑：控制中断必须连续 30 个周期无编码器运动，用户按键后重新检查设备，检查期间的运动也会阻止清故障；确认成功只回到待机。行驶中按键立即取消输出。
7. OLED 每次 Poll 只执行一个页设置命令或一个 16 字节数据块，先检查 BUSY，失败立即退出并退避；页命令失败不会继续发送余下命令。BUSY 在预检查后出现时，单次 HAL 等待仍可能达到约 26 ms，但不会再连续等待 4 次约 104 ms。
8. 调参堵转门限与 PWM 限幅联动；高输出无运动 500 ms 停止，任何正目标下持续 1 秒无正向编码器运动也停止，包括零增益/输出不足。稀疏的合法编码器脉冲会重置计时。电脑端还独立要求两侧全速平台平均反馈至少达到 `max(0.25, 0.1*peak)`；判定使用 100 Hz IIR 反馈，避免 50 ms 导出的单周期 raw 脉冲发生抽样混叠。

USART1 仍按原方案由视觉/调参启动模式独占。视觉接收在发送 START 之前开启；无识别帧手动启动仍保留原先蓝色 1 圈默认行为。没有改变 PCB 引脚。`.ioc` 中 USART1 中断优先级同步为源码已有的 1，避免重新生成时覆盖。

## 最佳参数进入普通模式

新增 `tools/autotune/export_profile.py`：读取本轮工具生成的 `summary.json`，验证以下内容后才原子写出头文件：

- 搜索来源为 `real_motor`，状态完整结束，没有以基线/回退漂移终止。
- 固件有 16 位构建标识，控制器契约与增量 PI/10 ms/IIR alpha=1/8/Kd=0 一致。
- 最佳参数有 3..5 次不同的实验记录和不同的原始 CSV，路径位于当前搜索目录内。
- 重读每份 CSV、重新检查有效性和运动情况、重新计算评分及重复实验统计，与报告一致。
- 同时导出左右编码器方向、PWM 限幅、已验证峰值速度及来源构建标识/报告 SHA256。

在仓库目录执行（`实际搜索目录` 必须替换为当前工具产生的成功实车搜索目录）：

```powershell
python tools/autotune/export_profile.py "实际搜索目录/summary.json" --output Core/Inc/motor_tuning.h
python tools/build_firmware.py
```

导出只生成源码配置，不连接串口、不烧录、不写 Flash。普通模式采用导出后的 Kd=0 和相同的非负输出/零目标取消策略，保持 PWM 上限；路线提出的左右轮速超过已验证峰值时按相同比例缩放，保留转向比例。

当前 `motor_tuning.h` 为 `CAR_TUNED_PI_ENABLED=0`，因为尚无实车结果；普通模式仍使用原默认速度 PID。模拟搜索结果不能导出。旧版报告缺少控制器契约与原始记录路径，也不能直接导入，需要用新版工具重新形成记录。测试目录中的启用配置仅为虚构编译夹具，没有写入生产配置。

## 验证结果

- `python tests/run_host_tests.py`：68 个 C 场景、39 个 Python 测试，合计 107 项全部通过。
- C 回归运行生产 `fsm.c`、`oled.c`、`control.c`、`mpu6050.c` 和 `autotune.c`；分别替换 HAL/业务接口。覆盖 1/2 圈、初始标记、窄标记、半计数、编码器回绕、ACBD 阶段和转向、传感器错误/间隔、丢线、所有 ACBD 阶段超时、故障确认及确认中运动。
- OLED/控制联合仿真：BUSY 预检查不调用阻塞 HAL；BUSY 在检查后出现时一次 Poll 只等待 26 ms，未触发 100 ms 目标超时；检查错误退避、每次一个事务及帧快照完整性。
- 低 PWM 20/50/79、零输出无运动会故障；稀疏运动不误判为连续静止。电脑端拒绝无运动数据，同时允许抽样 raw 为 0、实际滤波反馈有效的混叠情况。
- 参数导出测试覆盖模拟来源拒绝、漂移/不完整拒绝、原始数据与评分不一致、固件/参数不一致、越界或重复路径、重复实验数量和失败时不覆盖旧配置。
- 完整文件候选模拟搜索完成 12 次实验，来源明确为 `host_mock`，建议参数被复测接受；随后导出被正确拒绝。
- ARMCC5 单独编译了启用调参配置的真实 `control.c` 分支，只生成测试 `.o`，未生成启用虚构参数的可烧录镜像。
- 正式固件 ARMCC5 构建成功，0 错误、0 警告。构建标识 `3c2ab956f08746e7`，ROM 32324 字节，RW+ZI 12512 字节（含 4096 字节栈）。静态前台栈最大值 984 字节，调用图仍含未知间接调用项。

正式镜像为 `.build/firmware/ElcCarApp.hex`。本轮没有打开串口、驱动电机、烧录或请求 AI 候选。新的路口出口事件、灰度阈值、圈距离、航向方向、PWM/速度适用范围仍需在实际赛道和电机上标定；主机回归不能替代这些实车验证。
