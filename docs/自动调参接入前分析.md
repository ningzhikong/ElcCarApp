## 1. 总体判断

当前工程已经具备实车闭环的基本模块，但采样正确性、周期稳定性、路线事件和实验接口还不足以支撑可信的自动调参。建议先修复测量与调度，再建立独立速度环实验模式，最后接入 car 的自动搜索。

第一阶段目标应是“左右轮速度 PI 自动调参”。循迹 PD、航向 PD、路线计数与速度环分阶段验证；不要同时搜索全部参数。否则无法分辨评分变化来自电机控制、传感器、路线逻辑还是电池与地面变化。

## 2. 当前结构与实际控制链

| 位置 | 当前职责 | 评价 |
| --- | --- | --- |
| `Core/Src/main.c` | 外设初始化、按键轮询、10/100/1000ms 软件调度 | 结构直观，但阻塞任务破坏控制周期 |
| `Core/Src/control.c` | PWM、编码器、速度 PID、转向 PD、差速混合 | 把硬件和算法放在一起，缺少可独立验证的接口 |
| `Core/Src/fsm.c` | 状态机、灰度采样、视觉协议、航向积分、路线判断、OLED | 职责过多，显示任务还会修改控制状态 |
| `Core/Src/mpu6050.c` | IMU 配置、同步读取、启动零偏标定 | 有实际驱动，但超时和有效性处理需要完善 |
| `Core/Src/oled.c` | 帧缓存与阻塞 I2C 全屏发送 | 是当前控制周期的主要干扰源 |
| `Core/Inc` | 大部分头文件 | `control.h` 位于 Src，MDK-ARM 还存在不同内容的同名旧文件 |
| `ElcCarApp.ioc` | 芯片、引脚和外设配置 | 应继续作为引脚配置依据 |
| `MDK-ARM/ElcCarApp.uvprojx` | Keil ARMCC5 工程 | 提交了大量编译产物和个人环境文件 |

硬件映射：STM32F103C8T6，系统时钟 72MHz；TIM2 为左轮编码器，TIM4 为右轮编码器；TIM3 CH3/CH4 驱动左右 PWM，按当前配置约 18kHz；I2C1 驱动 OLED，I2C2 读取 MPU6050，均配置 100kHz；USART1 为 PA9/PA10、115200。

实际控制链：

```text
ABCD：灰度位置误差 / 临时航向锁定 → 共用转向 PD
ACBD：各阶段目前均使用航向 PD
                       ↓
        左右目标 = 基础速度 ∓ 转向修正
                       ↓
       左右增量式速度 PID → 有符号 PWM → 电机
                       ↑
       编码器计数 → 整数 IIR 滤波 → 速度反馈
```

状态为待机、视觉识别、ABCD、ACBD、刹车。PB15 实际承担状态切换和运行停车；PB14 虽命名 Start、配置为输入，目前没有被业务逻辑读取。

## 3. 接入调参前必须修复的问题

### 3.1 编码器反向计数被误读为高速正转

位置：`Core/Src/control.c:45`，定时器周期配置见 `Core/Src/tim.c`。

当前读取 0..65535 的计数器，直接转成 int32，然后判断是否小于零、取绝对值。这无法还原反向计数。例如从零倒数 5 个计数，CNT 为 65531，现有代码得到 32767，而不是 -5。

这影响反向运动、左右安装极性、差速转弯和制动。编码器错误可能被误当成 PID 问题，自动搜索无法修复。

建议：保持计数器自由运行，以当前与上一计数器之差按 16 位模运算还原有符号增量；前提是单个采样周期真实增量绝对值小于 32768。分别配置左右编码器符号，统一“车体向前”为正。不要在速度反馈处取绝对值；距离累计如需路程，应使用独立规则。自由运行差分还能避免“读取后清零”之间丢计数。

### 3.2 整数滤波引入明显低速偏差

位置：`Core/Src/control.c:62`。

`avg = (7 * avg + raw) >> 3` 是一阶 IIR，不是注释所说的八点移动平均。整数向下截断会造成偏差。从零状态持续输入时，按现有表达式计算：

| 恒定原始计数 | 稳态输出 |
| --- | --- |
| 1 | 0 |
| 5 | 0 |
| 10 | 3 |
| 25 | 18 |

这些是表达式的计算结果，不是实车测量。当前目标速度恰好为 10 和 25，因此偏差不可忽略。

建议用浮点状态或保留小数位的定点实现，反馈保持小数精度；原始计数和滤波速度同时保留。alpha=1/8 在真实 10ms 周期下已有约 75ms 时间常数，应根据采样噪声和控制带宽决定，而非默认越平滑越好。实验开始应重置滤波状态，避免上一轮影响下一轮。

里程应累计原始有符号计数，不能累计滤波并截断后的速度。

### 3.3 10ms 控制周期实际上无法保证

位置：`Core/Src/main.c:123`、`:130`；`Core/Src/oled.c:49`、`:159`；`Core/Src/i2c.c:42`。

控制函数由主循环检查 HAL_GetTick 调用，并不是定时中断。OLED 全屏 1024 字节，在 100kHz I2C 下只算数据和 ACK 就需约 92.16ms；考虑本驱动的地址、控制字节与命令，每帧约 100ms。main.c 每次显示任务连续调用两次 `FSM_OLED_Update()`，因此约阻塞 200ms。

由于一次显示已经超过 100ms 调度间隔，随后循环会继续满足显示条件。正常总线传输下，控制频率可能降至约 5Hz，而非设计的 100Hz；最终需要用 GPIO/时间戳测量确认。

同时还有按键消抖 `HAL_Delay(20)`、灰度每通道最长 10ms 轮询、IMU 单次 500ms 超时，以及 OLED 的 HAL_MAX_DELAY。由此导致：

- “脉冲/10ms”的速度单位失真。
- PID 的积分、微分实际时间尺度变化。
- yaw 仍乘 0.01，航向积分时间错误。
- 按键停车和未来软件心跳可能被延后。

建议为速度环建立独立、限时的 10ms 控制任务。可评估当前未占用的 TIM1 更新中断，无需输出引脚；car 的 TIM2 已在实车用于编码器，不能照搬。中断只做编码器快照、命令交接、保护检查、速度控制和小型采样入队；不要把整个 FSM、I2C、OLED 或文本格式化搬入中断。

显示改为前台分片/异步发送，仅使用快照；按键采用时间戳消抖。传感器采样需有时限和有效性标志。测量实际周期、执行时间与超期次数，明确超期后的处置；不要用补跑多次控制来掩盖缺失采样。

### 3.4 故障和停车接口不足以支持无人值守试验

位置：`Core/Src/main.c:205`、`Core/Src/stm32f1xx_it.c:85`、`Core/Src/fsm.c:460`。

Error_Handler 关闭中断后闪灯，HardFault 等异常进入死循环，都没有主动关闭电机输出。运行中发生异常时，硬件 PWM 可能继续保持之前的输出。目前也没有实验时长上限、通信心跳、堵转、超速或编码器异常的统一故障状态。

BRAKE 状态通过零目标速度闭环制动，但使用当前错误、无方向的速度反馈；PWM 可能跨过零并输出反向驱动。不能把它作为自动实验的唯一停止策略。

建议：增加统一故障锁存、独立最大实验时长、适合实车的心跳期限、编码器异常/超速/持续高输出低速度检查、控制超期处理。故障路径应能直接把 PWM 寄存器置零，并在硬件允许时控制驱动使能；恢复运行需要明确解除故障。看门狗仅在控制和前台健康条件满足时喂狗。

需要区分“驱动指令已停止”和“车轮物理停止”：分别返回状态，后者由有效测速、连续静止时间和最长等待时间判断。

若驱动确为 TB6612FNG 且 STBY 为高，当前方向脚一高一低、PWM=0 对应短路制动，不是高阻滑行。应明确提供 brake/coast/standby 的硬件语义，并实查 STBY 接线。不能照搬内部模型“零目标显式滑行”的评分假设。

## 4. 路线、传感器与外环问题

### 4.1 ABCD 顶点事件存在条件冲突

位置：`Core/Src/fsm.c:333`。

离开顶点时，`is_on_peak=false`，代码先把 `peak_maintain_pulse` 清零，再要求其大于 20。因此 `was_on_peak && !is_on_peak` 的离开事件无法通过外层条件。进入事件又只在第一个样本成立，如果首次样本未达到距离阈值，之后累计到阈值也不会补发事件。

建议独立实现顶点检测器，区分候选、确认、离开与重新使能；先保存事件所需状态，再清累计值。明确一次标记触发一次事件，不混合统计进入和离开。500ms 抑制可作为辅助手段，主要确认条件优先采用距离和传感器连续有效性。

`last_lap_encoder_tick` 在 ABCD 每次顶点事件都更新，因此终点的 3000 阈值实际比较的是距上个顶点的距离，而不是整圈距离。需拆分上次标记里程和本圈起点里程，并依据赛道需求重新定义计数与停车条件。

### 4.2 ACBD 沿线阶段没有实际循迹控制

位置：`Core/Src/fsm.c:385`、`:455`。

`ACBD_LINE_TO_B`、`ACBD_LINE_TO_A` 虽然扫描灰度，但最后始终用 target_straight_yaw 与 current_yaw 做 PD。灰度主要参与事件检测，未用于这两个阶段的转向。应根据真实赛道确认设计意图；如这两段需要沿黑线，应显式切为循迹控制。盲行、重新捕获线、稳定循迹应有独立进入条件和超时。

TO_C 有 10 秒超时，其余若干阶段没有同等的阶段期限。建议统一阶段时长/距离上限，避免漏掉标记后一直行驶。

### 4.3 显示函数修改采样历史，造成路线判断耦合

位置：`Core/Src/fsm.c:498`。

ABCD 的 OLED 更新会调用 GraySensor_Scan，修改 was_on_peak、is_on_peak 和 gray_error。控制周期之间的显示扫描可能消耗事件边沿。显示必须只读缓存快照；采样与事件检测只由确定的任务更新一次。

### 4.4 灰度建议先标定再优化控制

位置：`Core/Src/fsm.c:81`。

目前直接用原始 ADC 值计算重心，依赖黑线为高，阈值分散为 2600/2800/3000。背景偏置和各通道差异会影响位置估计；总和不足时旧误差继续保留，ADC 超时时也保留旧通道值，没有显式失线/失效状态。

建议每通道测黑白端点，统一极性并归一化；输出位置、置信度、有效通道数、交叉标记和失线状态。低置信度时采用限速、限时寻线或停车规则。检查 ADC 启动校准，并按模拟开关与信号源特性确定可测量的建立时间，避免依赖空循环次数。

### 4.5 航向与循迹不能共用一份 PD 状态和参数

位置：`Core/Src/fsm.c:163`、`:372`、`:455`。

初始化时先设置转向参数 8/2/5，随后覆盖为 22/8/18，最终实际生效为后者。灰度误差和角度误差单位不同，却共用 pid_turn；模式切换也会共享上一误差，使微分产生不必要的跳变。

建议 line_pd 与 heading_pd 各自保存配置和状态，模式切换时重置或平滑交接。ABCD 基础速度 10、转向修正限幅 18，使目标速度可达 -8/28；如果不希望内轮反转，应显式限制转向修正与可行轮速，而不是依靠后续 PWM 限幅。

IMU 当前采用固定 0.01 秒积分；启动标定只要有样本便求均值，不返回标定质量，读取失败也未让依赖航向的运动进入故障。建议携带样本时间与新鲜度，检查静止条件、成功率和方差，失效时禁止继续依赖航向。Y 轴是否对应偏航由当前安装决定，需要实车旋转核验，不宜直接改为 Z 轴。纯陀螺积分需考虑漂移，长期航向可结合赛道约束或轮式里程信息校正。

### 4.6 已选方案：USART1 在视觉与调参之间分时使用

位置：`Core/Src/fsm.c:179`、`:237`。

用户已选择保留现有 PCB 接线：正常使用时 USART1 连接视觉模块；独立速度环调参时断开视觉模块，原 USART1 接口改接 USB 转串口。无需启用 USART2/USART3 或迁移灰度、电机、蜂鸣器/LED 引脚。

正常模式保留 USART1 的 VISION 会话语义：只在需要视觉识别时接收视觉结果，只有 VISION 状态允许颜色和圈数生效。调参模式独立使用协议、缓冲、心跳、遥测、实验状态和错误统计，在该模式下持续接收主机命令，不运行视觉解析或发送视觉 START。

两种模式必须显式选择、互斥使用 USART1；不能让两个模块分别定义同名 HAL 回调或同时重启接收。统一 UART 入口按当前模式分发字节和错误，切换时先停止运动、结束旧会话并清理接收缓冲。主机连接后先通过固件标识/模式握手确认处于调参模式，再发送实验命令；普通串口字节不能直接启动实验。

调参模块通过统一控制接口读取快照、提交整组参数和申请实验控制权，路线与实验不能同时驱动电机。实验心跳只约束已启动的调参会话；正常模式不依赖 PC。调参模块可编译关闭，电机保护和稳定控制周期仍属于公共基础设施。

逻辑接线如下；这是 MCU 信号对应关系，不代表 PCB 排针的物理顺序，实接应核对丝印或原理图。使用 3.3V TTL 电平，电源连接方式按实际板卡确认。

| USB 转串口 | MCU 信号 |
| --- | --- |
| RXD | USART1_TX / PA9 |
| TXD | USART1_RX / PA10 |
| GND | GND |

换接时先停止运行并断电；调参连接中视觉模块应断开，不能让视觉模块与 USB 转串口的 TX 同时驱动 MCU RX。该方案支持速度环独立调参，不支持视觉识别与 PC 调参同时在线。

用户提供硬件工程：`E:/workshop/纳新/f103小车.eprj2`。已只读识别为包含原理图与 PCB 项目结构的 SQLite 容器；尚未完成实际连接器引脚顺序与网络连通核对，不能把软件引脚表当成已验证的 PCB 接线。

串口资源核对结果保留作背景：USART2 的 PA2/PA3 已用于灰度与电机方向，USART3 的 PB10/PB11 已用于 MPU6050；两者其他重映射 TX/RX 引脚未在当前 LQFP48 封装引出。

## 5. 控制算法的取舍

当前速度算法是增量式 PID：

```text
Δu = Kp·(e[k]-e[k-1]) + Ki·e[k] + Kd·(e[k]-2e[k-1]+e[k-2])
Δu 限幅 ±30；累加输出限幅 ±400；底层 PWM 范围 ±999。
```

这些 Ki/Kd 隐含采样周期，不能理解为显式按秒定义的连续参数。输出增量限幅与总限幅也是受控系统的一部分，调参期间必须固定并写入实验配置。当前输出状态已限幅，不能简单认定存在无限积分累积；仍需定义饱和后的更新、反向、停止和重置行为。

建议先修复测量与时序、保留旧控制器取得可比较基准。建立清晰接口后，再比较显式 dt 的位置式 PI，初期 Kd=0；它更容易与 car 现有条件积分算法对应。更换算法需要重新建基准，不能保留旧增益宣称等效。若保留增量式 PI，也可以自动调参，前提是提示词、参数范围与评分器准确描述当前算法。

先做低输出开环阶跃，测左右方向、启动死区、稳定速度和动态响应，再决定实车参数边界与阶跃幅度。左右电机允许独立 PI 参数；不要先假定一组参数同时最优。前馈、死区补偿、电池电压补偿可在基础实验稳定后加入，每次结构变化都重新建立基准。

速度接口建议统一为 RPM 或 rad/s；换算需要每轮实际有效计数、减速比、编码器倍率及实际采样间隔。不能仅凭电机标称 PPR 直接换算。原始计数保留用于诊断和里程。

## 6. car 自动调参工具的复用边界

| 内容 | 建议 |
| --- | --- |
| Python 独占串口、收发日志、异常保存 | 复用架构，适配协议和故障类型 |
| AI 提候选、结构校验、单步限制 | 复用机制，重做实车参数配置与 schema |
| 候选重复实验、中位数/最差比较、回退 | 保留思路，加入真实噪声和工况控制 |
| AI 调用前停车 | 保留，并确认车轮静止后再进行耗时调用 |
| MCU 参数交接、ACK、心跳和固定实验时长 | 复用设计，接入真实驱动与故障状态 |
| TIM2 定时实现 | 不可直接搬：实车 TIM2 已占用于编码器 |
| Kp 0..0.02、Ki 0..0.1 | 内部模型范围，不能直接用于实车 |
| 固定 231 行、50ms、目标 50/120/60 RPM | 需要按真实系统确定实验配置 |
| PWM 0..1、速度 0..205、Kd 固定为零的校验 | 按实车单位、方向和输出范围重写 |
| 内部模型历史与 0.548 等评分 | 不能作为实车的初始性能基准 |

car 的 `ai_tune.py` 提示词明确写死内部一阶模型，`validate_candidate()` 也写死模型增益范围。`analyze.py` 对时间戳、目标序列、输出和速度都有模型专用断言。只改串口端口、替换 MCU 计算函数，现有流程仍不能正确评价实车。

建议以 experiment profile 管理算法名称/版本、速度单位、周期、输出范围、滤波、参数边界、目标序列和评分版本。主机与固件先握手校验 profile，再运行。结果 source 区分 host_mock、mcu_simulation 和 real_motor；算法、固件或关键配置不同的历史不得混作同一搜索历史。

## 7. 建议的最小可用接入方案

### 固件

- 独立速度测试模式，与路线运行互斥；首版关闭循迹与航向外环，直接给左右轮目标。
- USART1 按正常/调参模式分时使用；调参时断开视觉模块并换接主机，模块有独立协议与缓存，禁用时不改变正常路线行为。
- 始终只允许一个控制任务写 PWM；路线与调参通过目标接口提交命令。
- 参数整组提交，在控制周期边界应用，ACK 返回请求号、实际参数和配置版本。
- 通信具备版本/能力查询、参数读取、开始实验、状态、心跳、停止和数据导出能力。不要预先把命令字符串当成已经实现的协议。
- 数据样本至少包含请求号、序号、真实时间/周期、左右目标、原始计数、滤波速度、实际 PWM、饱和标志、状态及故障。实验元数据记录实际增益与固件/profile 标识。
- 采样数据有界存储或非阻塞传输；溢出和缺帧明确报错，不允许静默丢失后继续评成有效试验。
- 参数初期只存 RAM，正常选择出的结果先保存到主机报告；稳定后再考虑带版本与校验的持久化。

### 主机

- 在现有流程上抽离 Board/Experiment/Evaluator/CandidatePolicy 接口，用 profile 选择内部模型或真实双电机。
- 每次启动实测基准，候选失败恢复最佳参数并复测。算法、限幅或滤波变更后废止旧基准。
- 左右轮分别计算指标，联合决策需限制较差的一侧；不能靠平均分掩盖某一轮恶化。
- 先检查硬约束：故障、失联、超速、长期饱和、编码器异常、周期超期、数据不完整任一失败，直接判不可接受。
- 性能指标再使用跟踪误差、超调、调节时间、输出变化和左右不一致；将停止工况的制动策略固定下来。
- 真实电机有噪声、温升和电量漂移，沿用“中位数改善 1%”前需测量重复性；可采用基准—候选—基准的配对顺序、冷却/静止等待和超出噪声幅度的最小收益条件。
- 架空轮验证方向与基础稳定性，再在受控地面负载下复核。空载最佳参数不能直接视为落地最优。

STM32F103C8 的 RAM 为 20KB。旧日志显示约 3.5KB RW+ZI，但不是本轮构建结果。双轮遥测若每条约 48 字节、保存 256 条，已需约 12KB，应重新检查 map、栈与缓冲布局。若采用 50Hz、48 字节二进制样本，载荷约 2.4KB/s；115200/8N1 理论字节率约 11.52KB/s，但仍需计入协议、ACK、格式化开销和队列压力。文本不能直接套用二进制的带宽估计。

## 8. 项目整理建议

逐步拆分即可，当前无需先引入 RTOS 或更换开发工具：

```text
Core/                 CubeMX 生成的配置、启动与中断入口
App/                  路线状态机、运行模式、按键与显示任务
Control/              纯 PI/PD、差速分配、目标限速
Board/                motor / encoder / gray_sensor / imu 硬件适配
Experiment/           实验状态、参数交接、采样、保护与通信协议
tools/autotune/       主机适配器、profile、评分、候选校验
docs/                 接线、单位、协议、构建与验收记录
```

- 先拆 motor/encoder/speed_control 和实验模式，其余随改造逐步迁移，避免大规模重命名掩盖行为变化。
- 统一有效的 control.h，清理 MDK-ARM 同名旧头文件与无实现声明；修改工程时同步 include path。
- 确定源码实际编码后统一为一致编码，避免把 GBK 读取问题或已有混合编码直接批量覆盖成乱码。
- 增加 README、构建方法、烧录方式、引脚表、单位与协议说明。
- 添加适当 .gitignore，停止跟踪对象文件、链接产物、个人 GUI 状态、临时审查副本；构建记录/发布固件按需单独归档。
- 保留 CubeMX USER CODE 边界，新增业务模块避免重新生成外设代码时丢失。
- 软件修改提交、固件哈希、参数和实验报告建立关联，支持回到任一已验证基准。

## 9. 推荐实施顺序与验收

| 阶段 | 交付内容 | 通过条件 |
| --- | --- | --- |
| A | 编码器符号、滤波、计数里程、稳定调度、明确停机 | 正反转测量正确；低速无截断偏差；显示/通信不破坏周期；异常能取消驱动输出 |
| B | 独立速度实验模式、常驻串口、遥测与故障状态 | 手工固定参数可重复运行；ACK 与实际参数一致；STOP/超时/数据溢出行为可验证 |
| C | car 主机工具适配实车 profile | 保存完整实车数据；拒绝模型历史混用；评分正确处理双轮、噪声及故障 |
| D | 有界自动 PI 搜索、回退与复测 | 基准重复性足够；候选改善超过工况噪声；一轮失败可回到经复测的最佳参数 |
| E | 循迹/航向参数分离，修复路线事件，再优化外环 | 基础速度环固定，完成标记/圈数/失线验证后才比较路线性能 |

针对 A/B，应编写有区分力的检查：计数器正反向跨零与回绕、低速滤波、实验状态重置、参数边界与非有限值、半包/溢出重同步、超时/故障停机、顶点一次触发及离开事件。主机模拟检查与实板实测记录分开保存。已有编译日志中的“0 错误 0 警告”只能说明当时构建通过，不能替代这些行为验证。

接入前还需实查：编码器有效每轮计数和符号、车轮尺寸、电机与驱动型号及 STBY 接线、供电与正常负载、视觉接口的物理引脚顺序与断开方式、灰度黑白范围、IMU 安装方向。没有这些信息时，可先完成静态修复、接口与离线验证；实车限幅和实验目标不能照抄内部模型。
